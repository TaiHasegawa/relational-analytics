# 判断の例（合成データ100名）

`relana org-draft` の出力から、実際にどう判断するかの例。

## 材料

```json
{
  "manager_meetings": [
    {"title": "製品開発本部 マネジャー定例",
     "teams": ["u_001チーム", "u_009チーム", "u_019チーム", "u_025チーム"],
     "occurrences": 11}
  ],
  "teams": [
    {"team_id": "u_043チーム", "member_count": 13, "manager": "u_043",
     "meeting_titles": [{"title": "西日本 週次定例", "occurrences": 13}],
     "algorithmic_dept_guess": "部門2"},
    {"team_id": "u_031チーム", "member_count": 12, "manager": "u_031",
     "meeting_titles": [{"title": "東日本 週次定例", "occurrences": 13}],
     "algorithmic_dept_guess": "部門2"},
    {"team_id": "u_009チーム", "member_count": 10, "manager": "u_009",
     "meeting_titles": [{"title": "コア 週次定例", "occurrences": 13}],
     "algorithmic_dept_guess": "部門1"},
    {"team_id": "u_001チーム", "member_count": 8, "manager": "u_001",
     "meeting_titles": [{"title": "パッケージング 週次定例", "occurrences": 13}],
     "algorithmic_dept_guess": "部門1"}
  ]
}
```

## 判断

**手順1 — マネジャー定例を使う。**
「製品開発本部 マネジャー定例」が4チームを名指ししている。この4つは確定。部門名も確定。

**手順2 — 定例タイトルからチーム名を取る。**
`u_009チーム` → 「コア」、`u_001チーム` → 「パッケージング」。

**手順3 — 残りをタイトルの意味で束ねる。**
`u_031チーム`（東日本）と `u_043チーム`（西日本）は地域で分かれた同じ機能。
同じ部門とみなす。ただし**部門名はタイトルに現れていないので推測**になる。
「営業本部」と仮置きし、利用者に確認する。

**注意した点 —** `algorithmic_dept_guess` では `u_001チーム`（パッケージング）が
`部門1` に入っているが、マネジャー定例の方が信頼できるのでそちらを採用した。

> アルゴリズムは、部門を跨ぐ橋渡し役がいるチームを相手部門に吸い寄せてしまう。
> これが最も多い誤りのパターンで、タイトルを読めば避けられる。

## 結果

```json
{
  "departments": {
    "製品開発本部": ["u_001チーム", "u_009チーム", "u_019チーム", "u_025チーム"],
    "営業本部": ["u_031チーム", "u_043チーム"]
  },
  "team_names": {
    "u_001チーム": "パッケージング",
    "u_009チーム": "コア",
    "u_031チーム": "東日本",
    "u_043チーム": "西日本"
  }
}
```

## 利用者への確認

営業本部は推測だと明示する。確信度の違いを隠さないこと。
