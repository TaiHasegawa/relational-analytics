# レポートの見た目の規約

このレポートは、人事担当者が**読んで判断するための文書**であって、
数値を見せるための管理画面ではない。文書として読める密度と静けさを優先する。

実装は `src/relana/report/assets.py` の `CSS` にある。
ファイル先頭に、この規約の要約をコメントで置いている。

## 6つの約束

### 1. 補足は「塗りのブロック」で示す。左の縦線は使わない

左に細い縦線を引くだけの引用スタイルは、文書の中で弱く、
注意書きなのか引用なのか見分けがつかない。
**薄く色を敷いた角丸のブロック**にし、先頭に記号を1つ置く。

```
❌  │ この指標の限界　この数値は人事評価に使えない
    ^ 2px の縦線だけ

⭕  ┌──────────────────────────────┐
    │ ⚠️  この指標の限界　この数値は人事評価に使えない │
    └──────────────────────────────┘
      薄い黄色の地 ／ 角丸 4px ／ 内側 14px･16px
```

記号で種類を分ける。色だけで分けると、見分けに色覚を要求することになる。

| 用途 | 記号 | 地色 |
|---|---|---|
| 補足・読み方 | 💬 | 灰 `--fill-gray` |
| 限界・注意 | ⚠️ | 黄 `--fill-yellow` |
| いまの状態 | 📍 | 青 `--fill-blue` |
| 打ち手 | ✅ | 青 `--fill-blue` |

### 2. 色の彩度を落とす。見出しに色をつけない

文字の色は**黒に近い1色**（`--fg`）と**灰**（`--mut` / `--faint`）だけ。
見出しを色で目立たせない。見出しは**大きさ・太さ・上の余白**で区切る。

色を使うのは次の3つに限る。

- 状態を示す小さな札（要対応・警戒）
- 塗りのブロックの地色
- 図の中の系列（部門の色分けなど）

色は1段階だけ用意する。濃淡を何段も作ると、どれが強いのか読めなくなる。

```
--ok:#448361  --watch:#cb912f  --warn:#d9730d  --crit:#d44c47  --accent:#337ea9
```

**例外: ネットワーク図の部門の色だけは、トークンではなくデータから作る。**
部門の数は会社によって変わるので、固定の8色では使い回しが起きる。
離れた2部門が同じ色になると、図の上で同じ部門に見える。

`src/relana/report/graph_data.py` の `_dept_legend()` が、名簿の上位区分
（`family`）ごとに色味を決め、その中で明るさを変えて**1部門ずつ別の色**にする。
同じ本部だった部門は同系統の色になるので、2階層を名前で出さなくても
近さが図に残る。ここ以外で `hsl()` を直接書かない。

### 2b. 太字にするのは「固有名詞」と「数値」だけ

文を丸ごと太くすると、どこが部門名でどこが数値なのか分からない。
灰色の説明文も同じで、全部が同じ濃さだと読む順が決まらない。
**誰の話か（固有名詞）と、どれだけか（数値）**の2つだけを `<b>` にする。

```
❌  運営本部の18名には、部門の外とのつながりがほとんどありません
    ^ 文全体が 600。どこを見ればよいか分からない

⭕  **運営本部**の**18名**には、部門の外とのつながりがほとんどありません
    ^ 文は 400、固有名詞と数値だけ 700
```

灰色（`--mut`）の説明文の中では、太字にした語を `--fg` に戻す。
色は増やさない。**太さと明度の差**だけで、目が止まる場所を作る。

実装は `src/relana/report/pages.py` の `_emph(text, names)`。

- **固有名詞は推測しない。** 文字列から探すと「本部」「チーム」のような一般語を拾う。
  `src/relana/core/summary.py` が `names` に入れた名前だけを太字にする
- **氏名の末尾の番号（石井089）を太字にしない。**
  単位（名・%・倍・件・組・つ・割・本・人）の付いた数だけを拾う

### 3. 影を使わない

影は**実際に他の要素に重なるものだけ**に使う。この画面では図の吹き出しだけ。
カード・パネル・表に影をつけると、文書ではなく管理画面に見える。

面の区切りは次の2つで出す。

- 1px の薄い罫線（`--line` = 黒の 9%）
- 背景色の差（`--panel2` = ごく薄い灰）

カードを並べるときは、1px の隙間を罫線の色で埋めて**地続きの表**に見せる。
カードごとに枠と影をつけると、同じ情報が何度も囲われる。

### 4. 角丸は 4px

`--r: 4px` だけを使う。12px のような大きな丸みは、
文書の中で要素だけが浮いて見える。札（タグ）も 3px の角丸にし、
丸ピル型は使わない。

### 5. 区切りは余白で出す

見出しの**上に大きく、下に小さく**余白を取る。
これだけで節の切れ目が分かるので、罫線を引かなくてよい。

```
h2  上 38px / 下 2px
h3  上 26px / 下 2px
```

本文は 17px / 行間 1.55（`html{font-size:17px}` ＋ `body{font-size:1rem}`）。
説明文の幅は 72 文字で止める。1行が長いと目が戻る位置を見失う。

**小さい文字は 13px を下回らせない。** 大きさは `rem` で書く。
`px` で書くと基準を変えても追従せず、そこだけ小さく残る。

| 用途 | 目安 |
|---|---|
| 見出し（h1 / h2 / h3） | 34 / 22 / 17px |
| 本文・表 | 15〜17px |
| 説明・注記 | 14〜15px |
| 札・補助 | 13px |

### 6. 操作の反応は背景色の変化だけ

ホバーで**浮かせない・動かさない・影を足さない**。
背景を黒の 3%（`--hover`）に変えるだけにする。
`transform: translateY(-1px)` のような動きは、押せる場所が多い画面では
視線が常に揺れることになる。

```
❌  a.card:hover{transform:translateY(-1px);box-shadow:0 8px 22px …}
⭕  a.card:hover{background:var(--hover)}
```

遷移時間は 0.08s。それ以上かけると、反応が遅れて感じる。

## 新しい要素を足すとき

既存のトークンだけで組む。新しい色・新しい角丸・新しい影を定義しない。

| 作りたいもの | 使うもの |
|---|---|
| 注意書き | `.note` / `.note.limit` |
| 数値のまとまり | `.cards` + `.card`（罫線で地続きに） |
| 文章と図の入れ物 | `.panel`（枠線のみ、影なし） |
| 状態の札 | `.tag.ok` / `.watch` / `.warning` / `.critical` |
| 人や部門の明細 | `.person` |
| 一覧 | `_table()`（横罫線のみ・縞なし） |

## 確認する

```bash
.venv/bin/relana demo --no-open
```

`snapshots/demo/report/` を開き、次を見る。

1. **影が出ていないか。** 出てよいのは図の吹き出しだけ
2. **見出しに色がついていないか**
3. **角丸が 4px より大きい要素がないか**
4. **ホバーで要素が動かないか**
5. **幅 400px で横スクロールが出ないか**
